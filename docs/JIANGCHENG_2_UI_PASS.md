# 江城万物怪 2.0 · UI 优化 pass（Batch 2 之前）

> 日期：2026-11-19 ｜ 范围：`src/v2`（2.0 探索切片）；P1 旧版样式与交互保持不动。
> 目标：在进入 Batch 2 之前，把「能玩」提升到「看起来是一个被设计过的观测手册」，重点解决三处用户直接指出的问题：**属性不明显、标签没有颜色、战斗操作字太小**；并把纯文字地图改成一张可读、可玩的江城渡运图。

---

## 1. 设计方向

**现场速写 + 标本标签。** 2.0 的世界观是“拍下日常物件、确认物性、召唤回响”；UI 不应该像通用后台，而应像：

- 一本在江边被翻旧的**观测手册**：纸面、方格、孔版双色、红色批注；
- 每只生物是一张**标本标签**：属性色条、学名、数据行、证据标签；
- 地图是一张**渡运观测图**：手绘河道、桥、五区、五站航线，而不是按钮列表。

一次冒险（aesthetic risk）：**整张地图用虚构的 RISO 印刷地图来画**，不引用真实武汉地图照片，也不放任何与游戏无关的风景图。它看起来是这个世界自己的地图，而不是素材拼贴。

保留的品牌资产：纸张 `#faf8ef`、墨色 `#14212b`、RISO 红 `#e2402b`、RISO 蓝 `#1b4e75`、宋体标题 + 苹方正文、硬边、方格纸、印章与批注语法。

## 3. 字号、间距与组件

### 3.1 字号

从 9/10/11/12/13/14/22/26/34/72px 的散点，收到 7 级：

| 角色 | 尺寸 |
|---|---|
| 页面大标题 / 空态主张 | 30–40px（宋体 800） |
| 分区标题 | 24–32px（宋体 800） |
| 节标题 / 敌人名 | 18–26px（宋体 800） |
| 卡名 | 20px |
| 正文 | 15.5px（行高 1.6） |
| 小字 / 数据 | 13.5px（行高 1.5） |
| 微标签 / 徽章 | 13px（不再有 9–11px 的可读文本） |

数据统一 `font-variant-numeric: tabular-nums`；除 SVG 内真实代码/数字外，v2 不再使用等宽字体（原来的 `IBM Plex Mono` 标注被正文/数据字体替代），字体从 3 种降到 2 种（宋体 + 苹方）。

### 3.2 间距与组件

- 间距 token：4 / 8 / 12 / 16 / 24 / 32 / 44px；
- 按钮：常规 40px、大 48px、小 32px，全部方角（2px 印刷感），主按钮墨底、次按钮描边、ghost 下划线；
- 徽章：26px 高、13px；维度色与语义色统一；
- 样本卡：56px 字形 + 名称 17px + 属性/倾向徽章；
- 标本标签：84px 立绘 + 名称 20px + 四格数据 + 技能/证据标签；
- 证据 chip：58px 双层（维度 kicker + 标签名 + 来源），点击确认后红边；
- 战斗操作：主战 2×2 技能/普攻/防御 + 支援换位区 + 战报栏，桌面三栏，移动端单列。

## 4. 逐屏

### 捕获站
- 空态从一张空面板改为「先看物性，再定形。」+ 三步读法（看 / 确认 / 定形），并解释证据会改变能力，而不是只改文案。
- 样本卡现在能一眼区分 **属性（机巧/早味/木叶/江流/铁骨）** 和 **倾向（守护/诡计/支援/机动/强攻）**。
- 确认页：证据按维度颜色分组；新增“你确认的物性正在改变它”的因果行（例：`遮挡 → 伞骨突刺`），让规则变化可见。
- 移动端选择样本后自动滚到确认面板，减少“点了没反应”的错觉。
- 移除顶部 kicker 和“读取方式”小标签，让标题自己承担层级；也去掉等宽小字。

### 我的队伍
- 三个上阵位改成三张标本标签；默认主战红框、支援位虚线；属性/倾向/战绩/HP/ATK/SPD 一行可扫。
- 收藏区两列标本卡；替换技能用“装备 chip”，选中蓝边。
- 出发按钮升为 48px 主按钮，和次级操作拉开层级。

### 江城地图
- 新增「江风渡口 · 渡运观测图」：地图题头 + 图例（渡口路线 / 江流 / 未开放区域）。
- 画面：两片陆地、主江 + 支流、拱桥 + 斜拉桥、五区色块与标注、五站编号与当前站说明、渡船、罗盘、虚构比例尺。
- 地图下方是五站图例（编号与地图形状一致），再往下才是当前节点详情与选择。
- 移动端不压缩整张地图，改为竖向渡口路线（保留河流底纹与状态色），避免 390px 下地图文字不可读。
- 地图中的比例尺/罗盘/虚构声明明确它不是真实武汉地图。

### 探索战斗
- 敌人区：属性、阶段、HP、状态、意图、AI 来源与理由；AI 理由太长时换行而不是缩字。
- 我方：三张成员条，主战红框、HP 条、状态、支援冷却。
- 操作台：技能（共鸣/威力/冷却/免费 + 名称 + 说明）、普通攻击、稳住防御；支援/换位/连携两列；战报独立栏。
- 反馈：敌人/成员受伤时飘 `−N`、受疗 `+N`；每回合红章“第 N 回合”；受击轻微抖动；全部支持 `prefers-reduced-motion`。
- 支援按钮从“点击准备”缩为“准备/已备”，名字和状态不再抢行。

### 图鉴 / 结算
- 图鉴两列标本卡，锁定状态清晰；旧版 P1 图鉴与最近 AI 调用折叠为附录，不再是一堵文字墙。
- 结算页保留“胜/负”大印章、复盘、决策来源、探索进度；主操作按钮更大。

## 5. 动效与可访问性

- 屏幕进入 0.36s 上浮淡入；样本卡、图例、标本卡、技能/支援按钮按 0.04–0.16s 错峰；
- 召唤演出、地图小船漂浮、当前站脉冲、受伤浮字/回合闪字/抖动；
- 所有动效只改 `transform`/`opacity`，`prefers-reduced-motion` 下全部关闭；
- 按钮/链接有 hover、active、focus；移动端最小点击高度 ≥44px（战斗按钮 88px+）；文字对比使用深墨而非浅灰。

| design-taste-frontend inspector | 3 FAIL / 4 WARN（见下，均为品牌/题材取舍） |

### Inspector 剩余 3 个 FAIL 的说明

1. **`palette-claude`（奶油纸+赤陶红）**：这是 2.0 立项就冻结的品牌色（P1 孔版双色），不是模板默认；换掉会破坏 P1 → 2.0 的连续性，保留。
2. **`few-pictures`（0 张实拍/位图）**：本作的核心资产是程序化生成的 SVG 回响灵与手绘地图；引入武汉实景照片会与“物件成精”的世界观冲突，且有版权/隐私风险。地图/立绘均为项目自有绘制。
3. **`outlined-box`（1px 描边盒子）**：观测手册的表单/标本标签需要细线框；已把主要 1px 提升到 1.5px，剩余线框是有意的印刷语法。

WARN（可辩护）：无视频（题材不需要）、10 种字号（游戏数据密度需要）、9 个入场元素（已达到“有动效”但不到 16 的阈值）、虚线标签（“补充标签”本身是可点的添加动作）。

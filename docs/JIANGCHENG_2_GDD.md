## 0. 最终推荐的产品形态（只给一个答案）

**《江城回响录》：一款单机、免注册、浏览器运行的“现实物品 → 原创江城怪物 → 队伍探索战斗”收集 RPG 原型。**

- 入口仍是“拍/传一件物品”，但捕获结果从“一张卡”升级为**一个可解释、可养成、有明确战术职责的角色**。
- 主线不再是单卡 3 回合，而是**三人队伍 + 区域地图 + 机制 Boss** 的 5–12 分钟探索循环；原三回合快斗降级为「60 秒快斗」入口，保留 P1 全部资产。
- 首个可展示版本（比赛窗口内）做**两个区域**的完整纵向切片；完整 2.0 目标为五区域，分批建设。
- 不做账号、联机、GPS、抽卡、付费、排行榜；不做“AI 仪表盘”。

**一句话验收**：玩家拍一把雨伞，十分钟后能在江风渡口的暴雨 Boss 战里用它救下队友；第二天他会为了给热干面找一条缠绕分支而再拍一件新物品。

## 2. 三条核心循环（含状态变化与验收）

### 2.1 微循环 20–60 秒：捕获—惊喜—马上试用

| 步骤 | 玩家输入 | 规则状态变化 | AI 职责 | UI 反馈 | 失败恢复 | 测试方法 |
|---|---|---|---|---|---|---|
| 1. 拍/传/选样本 | 图片或样本 | 生成 `CaptureEvidence`（可见/推断两类） | `analyze_object` 给出可见特征、标签建议、角色倾向 | 显影 + 特征来源标注（◉ 可见 / ○ 推断） | 无 Key → 本地像素摘要；仍可继续 | 同图同纠正 = 同结果；12 类物品单测 |
| 2. 确认/纠正 | 最多改 3 个标签（类别/功能/形状） | 写入 `user_confirmed` 证据；重新编译 | 不参与（纯规则） | 能力预览与“为什么”卡片同步变化 | 改错可随时再改，免费 | 纠正后模块变化快照测试 |
| 3. 选择成长倾向 | 二选一（如守护 / 机动） | 生成 3 主动 + 1 被动，构建预算不变 | 提供合法能力候选与命名/叙事 | 形体增加对应配件/纹样，召唤演出 | 未选择前不落盘，不丢卡 | 预算边界测试 |
| 4. 一键试用 | 点击“加入队伍/快斗” | Quick Duel v1 或首次教学战 | `battle_director` 选敌方行动（首回合） | 60 秒内看到自己的选择改变结果 | AI 降级规则照常 | E2E：捕获→快斗 |

### 2.2 中循环 5–12 分钟：探索—组队—事件—战斗—解锁

```
江城地图选区域 → 进入区域节点图（每次 3–5 个节点）
  → 节点：普通战 / 精英战 / 事件 / 休整·采集 / 任务 / Boss
  → 每次节点结束：至少得到 1 个可见变化（新技能选项 / 材料 / 羁绊 / 地图节点 / 图鉴发现 / 剧情）
  → 区域 Boss：机制战，带阶段预告；胜后解锁下一区域与一个长期能力
  → 回城：队伍工坊编成、进化预览、图鉴归档
```

**硬验收**：每个中循环至少一次“新变化”；不允许“打了三场但什么都没变”。

### 2.3 长循环 30–90 分钟：区域图鉴—进化—区域挑战—世界推进

- 五区域按三幕推进，第一幕两区域可自由选择顺序；至少一个选择改变后续支援方式。
- 完成区域目标 → 获得“区域信物” → 解锁进化分支/新地图节点/Boss 挑战变体。
- 通关主线后保留：自由捕获、周目变体、挑战码复玩、图鉴补全。

## 3. 支柱一：物品语义编译器（从“AI 给设定”到“规则可解释”）

### 3.1 白名单标签维度（禁止模型发明）

| 维度 | 枚举值 | 用途 |
|---|---|---|
| `category` | food / tool / nature / vehicle / building / stationery / textile / toy / other（9） | 基础种族倾向 + 区域生态 |
| `shape` | round / long / flat / foldable / layered / branched / hollow（7） | 技能形态与命中方式 |
| `texture` | smooth / rough / woven / soft / rigid / liquid_like（6） | 被动与状态倾向 |
| `function` | protect / carry / connect / bind / illuminate / nourish / propel / decorate（8） | 主动技能语义核心 |
| `theme` | river / rain / flower / street_food / bridge / campus / invention / generic（8） | 世界观与区域适配、少量天气加成 |
| 证据来源 | `vision_observed` / `model_inferred` / `user_confirmed` | 决定 UI 标注与编译权重 |

### 3.2 编译算法（纯函数，确定性）

```
compileCreature(input: {
  vision: VisionSummary,             // 复用现有 64px 像素摘要 + 模型视觉摘要
  evidence: FeatureEvidence[],       // 标签 + 来源 + confidence
  corrections: UserCorrection[],     // 用户确认/覆盖
  buildChoice: BuildPath,            // 玩家二选一/三选一
  variant: number,                   // 稳定 variant（沿用 P1 hash）
}): CompiledCreature
```

1. **合并证据**：`user_confirmed` > `vision_observed` > `model_inferred`；冲突时用户确认胜出并记入 `conflictNote`。
2. **路径匹配**：按 `function + category + shape` 给 5 条 build path 打分；玩家选择固定 build，标签只决定“同 path 内的模块组合”。
3. **模块选取**：每条 path 有 6 个候选主动（每个带标签亲和），取标签匹配分最高的 3 个；被动同理取 1 个；全部来自白名单表（见 §3.3）。
4. **数值预算**：`hp/5 + atk + def + spd` 落在 **68–75**（按 P1 五只样本实测 69–74 设定），按 path 权重分配；**物品价值、稀有度、图片好看程度不进入预算**。
5. **稳定 ID**：`hash(normalizedTraits + corrections + buildChoice + variant)` 决定同分模块的排序，保证同输入同结果。

**AI 输出（仅建议，不决定数值）示例**：

```json
{
  "observed": [
    {"tag": "foldable", "source": "vision_observed", "evidenceText": "可折叠伞骨"},
    {"tag": "protect", "source": "vision_observed", "evidenceText": "伞面遮挡"}
  ],
  "inferred": [{"tag": "rain", "source": "model_inferred", "confidence": 0.82}],
  "categorySuggestion": "tool",
  "roleHint": "guardian",
  "passiveHint": "canopy_shield",
  "name": "伞跃跃",
  "flavor": "下雨的时候最爱逞强，伞面一开就觉得自己能挡住整条街。",
  "confidence": "high"
}
```

编译器收到后：`user_confirmed` 可覆盖 `protect/foldable`；`rain` 只影响 theme 与少量天气协同；最终 `stats/modules/passive` 由 `compileCreature` 生成，模型不能输出 `stats`。

**为什么不是简单映射**：标签只提供“倾向分 + 可解释来源”，最终动作仍是白名单模块；模型不能创造“攻击 +999”。

### 3.5 用户纠错（一次点击，不是表单）

- 捕获结果页显示 3–5 个「证据标签」，每个带来源徽标：`◉ 看见` / `◌ 推断` / `✓ 我确认`。
- 用户只能修改白名单标签（点选胶囊），最多 3 个；每次修改即时重算能力预览，并显示“这次修改改变了哪个机制”（例如“`遮挡` 让你获得开伞屏障”）。
- 纠错不改变数值预算，只改变模块组合与来源记录；**AI 只提供候选与叙事，不参与最终数值**。

## 4. 支柱二：队伍与 Expedition v2 战斗

### 4.1 编成与位置

- 队伍固定 3 只：1 只**主战（Active）**，2 只**支援（Reserve）**；战斗前可调整顺序与技能。
- 每只精灵拥有 3 个已知主动（编译产生），**装备其中 2 个**，加 1 个被动。
- 支援位不进行普通攻击；每只支援提供 1 个**支援指令**（由编译路径决定，如“援护 / 补给 / 侦测 / 反折”），冷却 2 回合。
- 战斗开始时选择首发主战；主战倒下时，下一位支援以 30% HP 自动登场；三人全部倒下判负。

### 4.2 回合结构与行动预算

每回合玩家拥有 **1 个主战行动 + 1 个支援指令**（顺序由玩家选择），随后敌方行动。这让“换位/支援”不再是浪费回合的按钮，也不会让回合数膨胀。

| 行动 | 花费 | 说明 |
|---|---|---|
| 使用主动技能 | 按技能标注共鸣 | 造成伤害/控制/护盾/资源 |
| 换位（调出支援） | 1 共鸣 | 新主战本回合受伤 ×0.7；旧主战进入休息回 4 HP |
| 支援指令 | 0–2 共鸣 | 每个支援独立冷却，效果见其编译路径 |
| 连携（Link） | 2 共鸣，每场 1 次 | 需主战 + 支援满足标签组合，见 §4.4 |
| 防御（保底） | 0 | 受伤 ×0.5，获得 1 共鸣；避免无招可用 |

**共鸣资源**：初始 2，上限 6；命中属性克制 +1；使用防御/支援 +1；被 Boss 机制命中可能 -1。用于换位、强技能、连携，防止无限滚雪球。

### 4.3 状态（全部可读、可驱散）

| 状态 | 效果 | 叠加/持续 | 驱散 |
|---|---|---|---|
| 潮湿 | 受到江流伤害 +10%/层；速度 -1/层 | 最多 3 层，2 回合 | 早味补给、雾中听风 |
| 缠绕 | 下次行动延后，造成伤害 ×0.8 | 1 次 | 不驱散，靠行动消耗 |
| 脆弱 | 受到伤害 +15% | 2 回合 | 早味补给 |
| 护盾 | 吸收伤害 | 数值型，2 回合 | 被击破 |
| 蓄力 | 下次攻击 +6/层 | 最多 3 层 | 攻击消耗 |
| 反光 | 受击反弹 8 | 1 回合 | — |
| 过热（Boss） | 每层使 Boss 技能 +2 伤害；到 5 层触发大招 | 区域机制 | 打断/缠绕 |
| 标记 | 受到伤害 +15%，结束时追加 8 | 2 回合 | 不驱散 |

### 4.5 伤害公式 v2（确定性）

```
raw = power + 0.45×ATK − 0.30×DEF
damage = clamp( round(raw × 属性克制 × 状态修正 × 连携修正 × 0.62), 3, 55 )
```
- 与 v1 的差异：更高的 ATK 权重、更低的 DEF 权重、总缩放 0.62（v1 为 0.78）配合 5–7 回合与 Boss 高 HP。
- 所有修正来自白名单常量；`Math.random()` 只允许通过 `createRng(seed|stream|round)`；AI 不参与数值。

### 4.6 胜负、平局与回放

- **胜**：Boss HP 归零。
- **负**：队伍三人全部倒下。
- **超时**：达到 `maxRounds=7`（普通战）或 8（Boss）后按“Boss 剩余 HP% vs 队伍剩余总 HP%”判定；差值 ≤5% 判平。
- **回放**：`BattleReplayV2` 记录 `rulesetVersion + seed + partySnapshot + enemySnapshot + skillDefsVersion + 玩家行动序列 + AI 计划序列`；同输入重放必须一致（测试断言）。

### 4.7 完整一局示例：江风渡口 · 暴雨守卫（首轮 Boss）

队伍：热干面（控制）、雨伞（守护）、轮渡（机动）；Boss HP 180，两阶段（90 HP 进入第二阶段）。

| 回合 | 敌方预告（可读） | 玩家行动 | 规则结算 | 结果 |
|---|---|---|---|---|
| R1 | “暴雨将至（下回合压境）” | 热干面：缠线牵制 | 造成 10，Boss 蓄力被打断，热度 -1 | Boss HP 170；共鸣 2 |
| R2 | “大雨压境：无遮挡者受创” | 雨伞上场（换位 1 共鸣）+ 支援“铺伞” | 主战受雨伤 ×0.6，转“蓄潮 +2 共鸣” | 主战 HP 满；共鸣 4 |
| R3 | “潮水涌动：换位会被冲散” | 轮渡：渡航换位 + 支援“侦测” | 进入者获 8 护盾；揭示下阶段 | 主战 78/86；共鸣 3 |
| R4 | “暴雨连击” | 雨伞：开伞屏障 + 支援“早味补给” | 主战受伤 0.6×，回 12 | Boss HP 96；下回合进入 P2 |
| R5 | P2（≤90）：“积水成渊，换位代价降低但入水者受 4” | 轮渡绕后 + 热干面连携“渡航护盾”（2 共鸣） | 清潮湿、全队 10 护盾 | Boss HP 74 |
| R6–R7 | “收网” | 集中爆发 / 保命 | 伤害结算 | 若 7 回合未破，按 HP% 判定 |

**多解验收**：同一 Boss 至少验证 2 种可行打法（守护消耗流 / 控制打断流 / 速攻爆发流）；不能只有“堆最高攻击”。

## 6. 支柱四：成长、羁绊与分支进化

### 6.1 成长曲线（防刷级膨胀）

- 等级上限 5；每级只给 **+2 HP 或 +1 单项（二选一）**，总成长 ≤ +8 等效点。
- 主要成长来自**熟练度**：记录“守护/支援/输出/控场”行为次数，达到 5/10 次解锁对应模块变体（横向，而不是纯数值）。
- 经验来源：首次通关节点、任务、Boss；重复刷同一节点经验递减 50%，防无限刷。

### 6.2 分支进化（至少 6 组真实物品，全部可预览）

| 物品 | 分支 A（角色变化） | 分支 B（角色变化） | 视觉变化（SVG 层） |
|---|---|---|---|
| 雨伞 | 守护伞灵：开伞屏障强化，团队减伤 → **守护/支援** | 疾风滑翔者：轻身 + 先手 + 标记 → **机动/诡计** | A：伞面加厚/护盾纹；B：伞骨变翼 |
| 热干面 | 缠面牵制者：缠绕/延后/打断 → **控制** | 暖胃补给师：治疗/解控/共鸣 → **支援** | A：面条延长成链；B：碗形底座加汤勺 |
| 轮渡 | 渡航引路人：换位/护盾 → **机动/守护** | 雾航侦察者：侦测/闪避/先手 → **侦察/快攻** | A：船体加甲板；B：船头灯/雾纹 |
| 水杯 | 蓄潮容器：蓄能/爆发 → **资源/爆发** | 护罩水灵：护盾/续航 → **守护/支援** | A：杯身刻波浪；B：水环护罩 |
| 笔记本 | 复写记录员：复写/支援 → **支援** | 战术速记官：预判/连携 → **诡计/控制** | A：纸页展开；B：笔尺配件 |
| 樱花 | 落樱标记师：标记/追加 → **输出/诡计** | 花幕闪避者：闪避/回能 → **机动** | A：花瓣环绕；B：花幕披风 |

- 条件：等级 3 + 该物品对应区域通关 + 一次“印记事件”（不是刷 100 次）。
- 预览：两条分支都显示模块差异与外观变化；选择后旧形态记录进 `EvolutionRecord`，不销毁。
- 重置：花费 1 区域信物可回退分支（避免首次选择锁死），但保留已解锁图鉴。

### 6.3 羁绊

- 同一队伍共同出战 3 / 6 次解锁两档羁绊：第一档解锁**连携槽**（见 §4.4），第二档给一个可读的小被动（如“搭档受击时主战回 2 HP”）。
- 羁绊条件以标签组合表达（`protect + carry`），玩家可预测，不是隐藏好感度。

## 7. 支柱五：世界探索（首版两个区域，目标五个）

| 区域（虚构名） | 主题 | 独有机制 | 特色掉落 | 生态关键词 |
|---|---|---|---|---|
| 过早巷 | 清晨市井、热气、碳水的幻想街区 | **余温/热度**：节点越深入热度越高，可用补给降温或利用高热换伤害 | 早味配方、热度核心 | 食物、布料、热气 |

| 桥影工坊 | 桥梁、机械、城市交通 | **连接/断路**：用连接标签重接机关，改变敌人站位 | 机巧模组、桥契 | 建筑、工具、机械 |
| 樱语山坡 | 校园树影、樱花与旧建筑意象（虚构） | **树影/记忆**：选择帮助不同精灵改变 NPC 信任与隐藏路线 | 花叶材料、记忆碎片 | 植物、花、文具 |

**区域节点循环**：进入区域 → 3 条初始路线（普通/风险/事件）→ 3–5 个节点 → 中途休整/采集 → Boss 或宝箱 → 区域进度 + 图鉴发现 + 地图解锁。

**事件设计**：≥20 个高价值事件，每个必须有“选择 → 可观察状态变化 → 后续影响”，拒绝纯文字加减数值。示例（完整表见 WORLD_BIBLE）：
- 渡口修船：损失 2 材料，后续获得 1 个运输支援位（队伍第 3 位可提前出场）。

- 樱坡树影：用照明/标记连接两处树影，发现隐藏记忆与配方。
- 桥影机关：必须用连接标签重构队伍才能打开隐藏路线。
- 创想站装置：三种合法组合对应三种 Boss 弱点。

**地图不是真实 GPS**：全部为虚构地图节点；玩家可上传任何城市拍摄的物品，武汉主题是首个世界赛季。

- **区域信物**：区域级稀有资源，解锁进化/回退分支/挑战变体。
- 无付费货币、无广告、无签到。

## 11. 任务书 §20 的 12 个设计问题：明确回答

1. **三回合怎么迁移？** 快斗 v1 与探索战 v2 **共享“动作合法性 + 伤害/状态管线 + AI 计划注入 + 回放”四个下层模块，但规则版本隔离**：`quick_v1` 沿用 `MAX_ROUNDS=3`、2 技能、无队伍；`expedition_v2` 用队伍/共鸣/状态/5–7 回合。旧回放只跑 v1 结算器。
2. **特征如何可靠转技能？** 五维白名单标签 + 三源证据 + 用户最多 3 次纠正 + 24 模块库 + 固定预算 + hash 定序。AI 只建议标签与叙事，编译全部由规则函数完成（§3）。
3. **什么让玩家玩第二次？** 优先级：① 新物品带来新机制职责（拍不同物品真的不同）；② 地图节点/事件的新组合；③ 进化分支的可见变化与新连携；④ 图鉴收集与挑战码。数值成长排最后。
4. **进化如何避免刷级膨胀？** 等级上限 5、每级 ≤+2 等效点；成长以“分支换职责”为主（输出/守护/控制/支援/机动互转）；熟练度解锁模块变体；花信物可回退；6 组实例见 §6.2。
5. **队伍战怎么玩？** 1 主战 + 2 支援；每回合 1 主战行动 + 1 支援指令；共鸣 0–6 用于换位/强技能/连携；主战倒下自动换 30% HP 的支援；Boss 7–8 回合；完整流程见 §4.2–4.7。
6. **区域/Boss 差异？** 五区各有独立规则（热度/潮位/连接/树影/装置），Boss 有阶段与预告；不是换元素贴图（§5、§7）。
7. **AI 影响哪些字段？** 严格四任务 schema（§9）；`battle_director` 只能选合法 actionId + 台词/意图；`quest_director` 只能选合法 eventId；`evolution_guide` 只能推荐已解锁分支；`analyze_object` 只能给标签建议。时序：预取 + 缓存 + 关键回合 + 8s 超时 + 规则兜底。
8. **24 卡图鉴迁移？** 新增 `jcm.save.v2`，首次启动只读迁移 `jcm.gallery.v1`：保留全部卡（不截断），生成 `MonsterV2` 兼容记录，备份到 `jcm.backup.v1`；容量 120 且锁定卡不淘汰；导出/导入 JSON；失败回退到 v1 只读模式（详见 ARCHITECTURE §9）。
9. **哪些必须重构？** 不是重写：新增 `src/domain/*` 领域层与 `src/app/*` 状态层；`App.tsx:40` 的 5 屏状态机扩展为 7 屏并拆出 provider；`battle.ts`/`plan.ts`/`BattleView.tsx` **冻结为 v1**；`analyze.ts`/`build.ts`/`MonsterSprite.tsx` 复用并扩展。文件级映射见 ARCHITECTURE §3–4。
10. **最值得先做的视觉演出？** 「召唤定形」：捕获结果页角色从双色线稿 → 套印错位 → 落版成型，玩家选择的 build 决定配件层变化，全程 1.2–1.8 秒，用现有 SVG + CSS 实现（不依赖生图）。第二优先是“进化前后同屏对照”。
11. **可证伪的成功标准？** 5–10 名未参与开发的学生：≥4/5 在 90 秒内完成捕获到召唤；≥4/5 能说清自己一只怪为何独特；≥3/5 在首个节点后主动选择“下一节点/再捕获/进化预览”之一；≥3/5 首败后改变队伍或分支而非原样重试（详见 BALANCE_AND_ACCEPTANCE）。
12. **比赛窗口不可缺少什么？** 参赛可展示版本 = 语义编译器 + 召唤演出 + 三人队伍 + expedition_v2 + 江风渡口完整区域 + 风雨电台 Boss + 雨伞/热干面两条切片 + 进化分支 + 存档迁移 + 诚实 AI。其余三区/更多 Boss 属于完整 2.0，但不是提交前硬要求；计划中不删除。

**前 60 秒（必须真实可操作，不是剪辑）**：

1. 0–10s：点「雨伞」样本 → 显影 → 证据标签出现（曲面伞面 / 可折叠 / 遮挡）。
2. 10–20s：玩家点选“我确认：遮挡” → 能力预览出现「开伞屏障 / 遮挡本能」→ 选「守护」倾向。
3. 20–30s：召唤定形演出 → 卡面显示来源证据与三项能力。
4. 30–40s：加入示例伙伴（热干面/轮渡）→ 进入江风渡口第一节点（微型事件战）。
5. 40–60s：Boss 预告暴雨 → 玩家用雨伞开伞屏障 → 伤害被挡下 → 解锁下一地图节点 + 图鉴记录。

**视觉/演出清单（按优先级）**：
1. 召唤定形（新）。
2. 进化前后对照（新）。
3. 技能发动：角色位移 + 状态图标落下 + 伤害数字（在现有 `.damage-float` 上扩展）。
4. 换位：双角色快速交叉移动，落位有墨点。
5. Boss 阶段：印章式“阶段 2”盖下 + 背景网格变色（不引入渐变/玻璃）。
6. 连携：两条虚线相接 + 汉字合成印章。

保留：孔版双色印刷、方格观测本、图章/标尺；每区域一个第二强调色（过早巷 `--marker` 金黄、渡口蓝、桥影铁灰、樱坡藕粉、创想站青绿）。

**战斗反馈最低标准（每个状态/动作都必须有可见反馈）**：

| 触发 | 最低反馈 | 实现建议 |
|---|---|---|
| 施加/叠加状态 | 状态图标落印 + 层数数字 + 说明短句 | SVG 图标 + CSS `stamp-in` |
| 换位 | 双角色交叉位移动画 + 落位墨点 | transform 0.35s |
| 技能发动 | 角色前压/光效 + 伤害数字（暴击/克制加色） | 复用 `.damage-float` |
| 护盾吸收 | 数字变为「挡下 N」+ 护盾条 | 数值回显 |
| 连携触发 | 两条虚线相接 + 合成印章 + 全屏短震 | CSS + 短动画 |
| Boss 阶段 | 巨大「阶段 2」印章盖下 + 网格变色 | 1s 定格 |
| 失败 | 明确写出“第几回合、哪个机制导致失败”+ 建议 | 结算页文案模板 |
| 低血量 | 血条闪红 + 角色表情 hurt | 复用 P1 机制 |
| 移动端 | 触控目标 ≥44px；状态不靠颜色单独区分 | 图标 + 文字 |
| 无障碍 | `prefers-reduced-motion` 下全部动画降级为瞬间切换 | CSS media query |

## 14. 反挫败与失败恢复

- 战斗失败：结算页明确“失败原因（哪一回合的哪个机制）→ 建议改动（换位/换技能/换分支）”，并允许一键回到队伍工坊；不消耗关键资源。
- 捕获失败/模型超时：保留本地兜底卡（demo/fallback 标注），不阻断流程。
- 存档失败：保留内存态 + 提供导出 JSON，提示“未保存”，不静默丢卡。
- 区域卡关：提供 3 条备选路线，至少 1 条不需要特定标签；Boss 前有休整节点。
- 不会因为误选进化分支而永久失去旧形态：进化记录可回退（1 信物）。

## 15. 明确不做（设计反模式）

- 账号、社交、排行榜、联机 PVP、付费、抽卡、广告、签到；GPS/AR 强制。
- 让 LLM 写伤害/血量/胜负、生成任意代码、伪造 AI 成功。
- “稀有度=战力”、刷级碾压、无限材料刷取。
- 满屏 AI 仪表盘、聊天式 NPC 主玩法、渐变玻璃拟态、把地图做成真实地图截图。
- 未经素材授权的真实校园/地标照片；正式内容一律原创虚构并标注。

## 16. 规划自查（主动否定与修订记录）

> 按任务书 §21/§22.7 要求，先自我审查再定稿；以下是已发现并修订的问题。

| 自查项 | 原方案风险 | 修订 |
|---|---|---|
| **过度保守** | 曾考虑“只加敌人/图鉴锁定/调战术系数” | 已升级为语义编译器 + 三人队伍 + 机制 Boss + 两区地图；补丁式内容不作为主方案 |
| **伪 AI** | 曾计划“AI 只写战斗播报” | 明确四类受限任务；battle-director 在合法动作内选招并实际改变战斗；无 Key 标为规则模式；不把播报当 AI 影响 |
| **玩法空洞** | 地图若只是“节点+文本” | 每区至少一个独有规则（余温/潮位/连接/树影/装置），事件必须有规则后果；Boss 至少两种打法 |
| **成本过高** | 五区 + 全量 AI 导演 + 生图 | 比赛版只做两区、3 个 AI 任务、SVG 演出；生图列为可选增强，不作为必需 |
| **重复内容** | 五个区域若只换颜色 | 每区不同机制与掉落；敌人原型对应不同反制；演化分支改变职责而非换皮 |
| **数值膨胀** | 队伍/进化可能推高数值 | 预算 68–75 恒定、等级上限 5、模块消耗上限、进化换职责不换数值 |
| **技术过度设计** | 考虑过路由/状态库/Pixi | 改用无依赖 reducer + 屏幕懒加载 + SVG/CSS；不引入新运行时 |
| **比赛窗口不现实** | 完整 2.0 无法在 2.5 周全做完 | 明确区分“参赛可展示版本（两区）”与“完整 2.0 目标”；批次可裁剪但不虚报 |
| **旧资产破坏** | 新战斗可能重写 v1 | v1 冻结 + golden 测试；v2 独立规则版本；旧卡只读迁移不删 |

- 模型在 v2 快照下的合法选招稳定性（P1 实测 2/2 合法，但样本少）；
- 三人队伍 + 5–7 回合的默认时长能否压在 8–12 分钟；
- 12 类物品的标签识别准确率（需要真实拍摄测试）；
- 存档迁移在真实用户旧数据（不同浏览器）上的表现。

# 《江城万物怪》2.0：可玩性、指引性、UI 与互动性审查

- 审查日期：2026-11-20
- 对应 GitHub：<https://github.com/Leionel/jiangcheng>
- 审查基线：`master` / `1abe74457f1dbd612943f75ac278586c970c9ee2`
- 方法：检查 README、2.0 设计及实施文档、主入口/页面/规则/存档/任务代码、仓库现有桌面及移动端截图、自动试玩报告。**未自行运行游戏，也没有真人试玩录像或留存数据；体验判断是基于当前代码与截图的专家审阅，不代表真人测试结论。**

## 0. 核心结论

当前的主要瓶颈不是缺系统，而是系统之间缺少一个能够被新人直觉理解的游玩体验。

- 新用户最先看见大量系统词、证据标签、成长倾向、顶部导航、研究手册式说明，却没有先看见大幅的“物品变怪”奇观和明确的短期目标。
- 核心循环存在，但过于手续化：选物品→读证据→确认→选路径→召唤→编队→地图→事件→战斗→结算。玩家还未产生情绪投入，就被要求理解诸多系统。
- 纸张/宋体/细边框是一致的艺术方向，但整个场景都用文档排版承载，造物、地图和战斗缺少应有的视觉主角地位。
- 游戏内有实际的错误反馈与经济奖励传播问题，需要在设计改版前先修，否则界面即便更漂亮也无法建立“操作—结果”信任。

建议产品定位收束为：**拍下身边的物品，召唤一只独一无二的江城怪物，带它走进城市奇遇。** 用“现实物品变身”做短视频传播钩子，“城市奇遇+成长”做中期留存，而不是同时向新人展示所有系统。

## 1. 已确认的实现事实（不可误判为未做）

| 已有功能 | 当前实现 |
| --- | --- |
| V2 入口 | `?v2=1`；根路径 `/` 仍进 P1 旧版 |
| 捕获 | 8 个样本、图片上传、标签证据、多种成长路径、定形 |
| 战斗 | 三人队伍、主战/支援、换位、共鸣、连携、最多 8 回合、五区不同 Boss |
| 探索 | 五个区域、每区 5 节点、20 个事件、前序线索影响后续个别选项 |
| 长线 | 等级 1–5、20 个进化分支、25 项任务、羁绊、三层图鉴、挑战码 |
| AI | 物品识别、敌方行动选择、任务推荐、进化推荐；输入与动作被规则限制 |
| 质量保障 | 仓库报告称 95 项测试、E2E 截图和 1000 场平衡模拟通过；仅属作者自测报告 |
| 真实试玩 | `docs/PLAYTEST_REPORT.md` 只有 5 种自动策略，并非真人用户 |

不要把“增加教程”“添加更多事件”当作主要修复方法：现有系统已经包含这两类功能。

## 2. 从完整游玩看：问题逐层定位

### 2.1 进入游戏前 10 秒：没有先给出令人兴奋的承诺（P0）

- 默认访问根网址会进入旧版，V2 的五区探索通过 URL 参数进入。对面向真实玩家的产品会造成版本认知偏差。
- 捕获首页首屏的主角是说明文字、样本列表、纸质“看见/确认/定形”步骤，少了足够大的怪物、变身对比和一个显著的主 CTA。
- 顶栏同时出现捕获、队伍、地图、任务、图鉴、模式、指引、旧版切换。绝大部分入口不该在新人第一秒同权展示。
- “观测手册·探索切片 / VOL.02”“本地规则”“证据标签”“倾向”等开发者或规则性信息过早曝光。

**改法**：先突出一只代表怪物和“这只怪原来是雨伞”的变身视觉，主按钮仅“拍照召唤”，次按钮“先试玩一个”；第一只怪生成完成再解锁导航。默认进入 V2；开发/对照入口留在设置里。

### 2.2 从捕获到首次战斗：程序正确，但乐趣出现太晚（P0）

- 目前用户先核对多个证据标签，才看到正式召唤和第一场战斗。标签对技能的影响是真的，但解释方式是静态表格而不是“能力变化”的可感知动画。
- 召唤前已经提供较完整技能、外观预览，惊喜被提前消耗；召唤阶段短暂显示后直接转队伍页面，仪式感不够。
- 已有起始三人队伍，却仍通过 `nextStepFor` 在 `captures === 0` 时强推捕获，容易让想立即战斗的用户迷惑。
- README 的“60 秒首战”指 P1 快斗，不应直接外推为 V2 的新手体验达标。

**改法**：新人前两分钟使用简化玩法：选样本/拍照→变身大动画→“它将陪你打第一场”→教学战（两次简单行动）→获得奖励→再介绍编队/五区/标签进阶。保留深度确认给自定义捕获/后续编辑。

### 2.3 地图与探索：有世界，但世界缺乏行动性（P0/P1）

- 1200×720 手绘地图本身方向不错，但在桌面首屏中占据很高版面，关键“当前节点”和主行动位于更下方；移动端用列表代替地图虽可读，却减少了空间探索感。
- 五个区域均是事件→普通战→事件→精英→Boss 的一致模板，容易让后续区域只是换皮重复。
- 事件多为二选一与数值奖励；已有少量 flags 分支，但对队伍、角色、环境的反应深度有限。
- 事件文案有“用照明能力点灯”等角色能力话术，但 `applyEventChoice` 的前置约束仅检查 flag，不检查队伍是否真的带了照明能力。这让“自带物品改变世界”的承诺和实际机制存在落差。

**改法**：加入有记忆的区域 NPC、可回访地点、道具/属性改变事件选项、可见的世界状态变化。地图应有当前目标的视觉聚焦与紧随其后的行动按钮，而不把可操作信息埋在长篇资料下面。五区可以保留，但至少设计 2–3 条多步支线，并让一个早期 NPC 在后期重新出现，具体回应玩家过往选择。

### 2.4 战斗：策略系统不弱，但信息表达过重（P0）

- 战斗首屏主要展现回合、规则、属性倍率、AI 来源、种子、共鸣、意图、说明和角色状态；移动端实际攻击按钮需要进一步向下寻找。
- Boss 的攻击预告很实用，但页面把它表达为一堆文字、徽章和解释；缺少清晰的主“选择行动”区、强烈的技能反馈以及可预测的结果展示。
- 每回合“主战行动+支援/连携”机制需要有组合感，目前是先选支援再点击主战才结算，行为模型不易由控件本身推断。
- `battleDirector` 异步改变合法意图；玩家可能在模型计划返回前已经操作，屏幕上看到规则意图，而稍后使用 AI 意图。需确保意图不会在玩家可做决定期间改变而缺少提示；当前实现会根据回合归属更新，不阻止玩家立即行动，故应针对慢模型做专项体验测试。

**改法**：上层为敌我/场景主视觉，中层为只保留一条清晰预告的预警区域，底部采用粘性“行动盘”并区分“主行动”和“可附加支援”。重要招式展示预估伤害/治疗/资源消耗，一次点击即明确完成的是什么。首次战斗只开放少量基础招式，其余按需要解锁。

### 2.5 收集、成长和任务：内容丰富但奖励结构偏行政化（P1）

- 25 项任务在任务页以大量同形卡片同时铺开，视觉接近待办清单，而不是“下一段冒险”。
- 角色区分来源于固定标签、路径、模块和程序化形态组合，确有规则差别，但图像的独特度未必足以支持“我的物品变怪了”的核心幻想。
- 升级/进化更多是数值、技能和配色改变；进化后的轮廓/气质变化与伙伴关系表达仍需明显放大。
- 当前挑战码是复制字符串，不能等同于直接适合小红书分享的视觉作品。可以加带物品前后对照、怪物肖像、名称和城市故事的分享海报。

**改法**：把任务页重构为“当前冒险一件事、可领奖三件以内、其余收起”；成长以怪物形象、技能解锁演出、和玩家共同经历的故事记录为中心，数值保持在详情页；加入物品→怪物的高辨识分享卡，附挑战链接/二维码（在实际接入渠道时依据平台规则实现）。

## 3. 直接由代码定位的高优先级问题

| 优先级 | 问题 | 代码证据 | 风险/改法 |
| --- | --- | --- | --- |
| P0 | 根路径默认旧版，V2 仅参数开启 | `src/main.tsx` | 面向玩家时默认进入当前正式版，旧版放次级入口 |
| P0 | 事件“获得材料/信物”只更新 `RegionRunState` 局部材料，未增加 `SaveV2` 全局材料 | `src/v2/domain/region.ts` 的 `applyEventChoice` + `src/v2/V2App.tsx` 的 `chooseEvent` 仅 `patchRegionRun`；`save.ts` 的 `completeRegion` 也不汇总 | 玩家选择奖励，地图的全局材料数不变；确定经济口径并单点入账、做 E2E 断言 |
| P0 | `kind:'bond'` 被事件类型/内容引用，但 `applyEventChoice` 无 bond 分支 | `src/v2/domain/types.ts`、`src/v2/domain/region.ts` | 声称羁绊 +2 的选项实际上不提高 `SaveV2.bondPoints`；实现并测试 |
| P1 | “下一步”永远优先未完成区域，奖励/进化在主线期间几乎不会被推荐 | `src/v2/domain/guidance.ts` 的 `nextStepFor` | 动态推荐需根据资源/领奖/进化/卡点判断，而非单向优先级链 |
| P1 | 新手引导完成标识会滞后 | `src/v2/views/Guide.tsx`：队伍完成不仅需要三人，还要 `battles > 0` | 玩家已编满队伍仍可能看到“尚未完成”，改用实际目标状态 |
| P1 | 重新探索当前区域时直接创建新 run | `src/v2/V2App.tsx` `restartRun`，`src/v2/domain/save.ts` `startRegionRun` | 加确认/不可逆提示，明确是否保留当前区域线索与通关状态 |
| P1 | 部分事件强调特定能力，但操作约束只验证 flag | `src/v2/domain/region.ts` | 世界没有真正识别玩家携带的怪物能力；让能力要求与结果一致 |
| P1 | 存档限于浏览器本地 | `src/v2/domain/save.ts` `localStorage` | 换机、隐身模式、清理数据可能丢失；小工具发布前至少做清晰的存档机制 |
| P1 | 只有启发式自动玩家，没有真人可用性验证 | `docs/PLAYTEST_REPORT.md`、`docs/PLAYTEST_PROTOCOL.md` | 不能用通过率推断新手能理解或愿意复玩；安排 5–10 人观察 |

**需要区别**：第 2、3 项是源代码可直接确定的效果传播问题；其余是产品设计问题或需要验证的操作风险。这里未重跑测试，因此不声明具体线上复现频率。

## 4. UI 逐页重构建议

| 页面 | 当前问题 | 目标状态 | 修改方向 |
| --- | --- | --- | --- |
| 首屏/捕获 | 长说明、八个样本卡、术语过早、无主视觉 | 第一眼看到“拍物品变怪物” | 一只主角怪物+物品对照+单一主按钮；样本轮播；将标签规则折叠 |
| 捕获确认 | 多维标签与统计抢焦点 | 看到“确认会让怪物长出某能力” | 视觉连线、技能变化动画、默认只要求 1 个关键确认 |
| 召唤 | 展示后自动转场，缺惊喜 | 变身是整个产品的高潮 | 2–3 秒动态前后对照、跳过按钮、可查看与分享 |
| 队伍 | 同类卡重复、数字细小、技能像设置项 | 角色关系、主战/支援一目了然 | 角色头像更大，队伍站位线，技能变成可选择的图标卡 |
| 地图 | 艺术地图与实际行动分隔 | 当前故事节点一眼找到 | 当前位置高亮、行动浮层、NPC 与战斗点有图形差异 |
| 事件 | 纯文本选项与数值结果 | 冒险互动 | 场景插画、角色对话、选项即时反馈与后续影响回看 |
| 战斗 | 元数据先于怪物和行动盘 | 操作直观有节奏 | 敌我主视觉+意图条+固定底部技能栏+明显伤害动画 |
| 结算 | 多数内容是文字结果和统计 | 玩家有继续探索冲动 | 战利品显著展现、角色升级/新故事反馈、下一站一键继续 |
| 任务 | 25 卡全铺开 | 当前愿望与冒险路线 | 主任务重点卡、可领任务分组，其他折叠和筛选 |
| 图鉴 | 面板信息量大，卡面同质 | 让人愿意晒自己的怪物 | 大幅角色图、故事/战绩/进化相册、分享图可见 |
| 手机 | 头部导航与指引占大量首屏 | 手机单手可玩 | 底部 3 主入口、次级功能收起、粘性行动栏、缩短规则前言 |

## 5. 视觉方向：不要放弃“观测手册”，但要重新分配它的工作

建议选择“城市奇幻 × 轻冒险 × 温暖手绘”作为游戏主体；“纸张/标本/手记”保留在图鉴、事件回忆与详情弹窗中。

| 视觉层 | 使用方式 |
| --- | --- |
| 城市环境 | 更完整的场景插画与昼夜天气；避免地图只是附在手册里的平面图 |
| 怪物造型 | 不仅颜色变化，还要明显不同的轮廓、姿态、表情、配件和互动动作 |
| 主要交互 | 有足够大的按钮/技能图标；当前一步用明确色块强调，不用全靠细线框 |
| 卡牌 | 磨砂、纸张、印章可作为收藏视觉，而不是所有网页的基础容器 |
| 字体 | 宋体保留标题气质；说明文字用易读黑体；避免大量 13px 小字 |
| 动效 | 变身、攻击、命中、掉落、升级是优先；弱化无信息价值的炫光/hover |

避免“一次性全站重涂 CSS”。先针对**捕获首屏、召唤、战斗**做可看见差异的完整切片，验证用户反应，再推广到地图、任务与图鉴。

## 6. 推荐交付顺序

### P0：先在最小范围内让新人理解并感受到爽点

1. 修奖励传播和羁绊效果，补自动断言；默认正式入口改 V2。
2. 打通一个不超过 3 分钟的首次体验：极简首页→样本/照片→怪物惊喜→教学战→奖励→下一站。
3. 战斗移动端先改成“画面在上、操作在下”，操作按钮不藏在说明下面。
4. 给第一次召唤一个真正有表现力的结果页，结果页直接能进入教学战。
5. 主线引导从“规则字典”改为“当前唯一行动 + 操作时及时提示”。

### P1：让第一场战斗之后仍有理由继续

1. 区域事件从静态二选一升级为有 NPC 与物品能力检查的连续互动。
2. 任务只重点展示正在推进的内容，支持明确的领奖提醒。
3. 造物外观/进化明显差异，补个体经历故事。
4. 完成手机 UI 改造：底部导航、行动盘、情境提示、收纳高级系统。
5. 强化可分享内容：怪物图与现实物品的对照卡、性格/经历，分享后可回到游戏。

### P2：正式发布前验证

- 按设备分真人试玩 5–10 人，观察“无需解释是否进入第一战”“能否理解主战和支援”“第一场后是否愿意继续”。
- 测不同用户路径：只用样本、真实拍照、拒绝 AI、模型慢/掉线、战斗失败重试、存档导入、手机触屏。
- 记录事件效果实际入账、战斗意图稳定、进化可回退、已解锁区域不会异常被锁。
- 设计小红书场景的 30–90 秒试玩体验和分享回流，但先核对当时平台小工具的接入与审核要求。

## 7. 验收指标（建议目标，不是当前测量结果）

| 指标 | 建议门槛 |
| --- | --- |
| 首屏用途辨识 | 5 位新玩家中至少 4 位能在 10 秒内说出“拍物品变怪物然后冒险” |
| 首次操作成功 | 5 位中至少 4 位无口头提示完成样本捕获 |
| 进入第一战 | 中位时间 2 分钟以内，且无人因导航迷路而放弃 |
| 战斗可理解性 | 至少 4/5 能解释主战技能与支援的区别，找到防御入口 |
| 首次情绪反馈 | 口述/录像观察，有多少人主动关注怪物外观或选择保存分享 |
| 后续留存意愿 | 结束第一战后能否自发开始下一节点；不把“可继续点击”当作真正想玩 |
| 事件可信性 | 每项展示奖励与实际存档变化一致；关键资源 100% 有自动测试 |
| 移动端 | 首屏可触达主要行动，主要战斗按钮无需长滚动才能找到 |

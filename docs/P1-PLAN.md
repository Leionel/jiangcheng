## P1-B：改善 AI 的实际作用和动态表现

### P1-B1 敌方 AI 指挥官（核心）

- **当前问题**：`battle.chooseIntent` 是固定规则，AI 在战斗中完全缺席；玩家第二局面对同一敌人时出招可预测。
- **建议改动**：
  1. 新增纯函数模块 `battlePlan.ts`：从 `BattleState` 生成"可见状态快照"（回合、天气、双方 HP/属性/数值/技能、各招式由规则算出的预计伤害、玩家上一招、最近战报）；`sanitizePlan` 校验模型返回的 `skill` 必须属于敌方合法技能；`applyEnemyPlan` 把计划写回 `state.intent` 并记录来源。
  2. 服务端新增 `POST /api/battle/plan`：复用统一 `callModel`，提示词约束"只能从候选招式里选一个 + 给出 24 字内理由 + 26 字内战况播报"；输出过 zod；26s/客户端 6s 双超时；失败时客户端保留规则意图。
  3. `BattleView` 每回合请求一次计划（首回合最多等 6 秒，后续回合预取不阻塞输入）；意图条显示 `AI 选招 / 规则意图 / AI 超时降级` 与耗时；计划写入 `state.planLog`，结算页展示 AI 参与次数。
  4. 计划只影响"选哪招"，伤害、胜负、天气、先后手仍由 `battle.ts` 纯函数计算；同一 seed + 同一计划序列必得同一结果。
- **用户体验收益**：同一敌人会依据局面换招（低血回血、预判防御、抢手收割），第二局开始有"对手在应对我"的感觉；AI 的参与可被 AI 决策日志、意图徽章、结算统计三重验证。
- **实现复杂度**：中（服务端接口 + 客户端适配 + UI + 测试）。
- **依赖**：无（P1-A1、C1 可在其上叠加）。
- **验收方式**：
  - 单测：非法/越界/超时计划被拒绝并保留规则意图；合法计划正确写入 intent；`takeTurn` 在固定计划序列下可复现；`chooseIntent` 行为不变。
  - 真实接口：`scripts/ai-check.mjs` 调 `/api/battle/plan` 得到合法 `skill` 且 ∈ 敌方技能，耗时被记录。
  - E2E：AI 可用时首回合意图条出现 `AI 选招`，战报/结算出现 AI 参与次数；AI 不可用时明确显示 `规则意图`。

### P1-B2 战况播报

- **当前问题**：战报是模板拼接，没有"敌方指挥官口吻"的战场播报；规格书 §4.8 P1 明确要求。
- **建议改动**：并入 B1 同一次调用的 `taunt` 字段；显示在意图条理由后与战报顶部；不参与任何数值。
- **收益/复杂度**：小幅氛围收益；随 B1 一起做，边际成本接近 0。
- **验收**：真实接口返回值包含非空 `taunt`；界面出现；不改变战斗结果（同 seed 同计划序列结果一致）。

## P1-A：显著改善核心玩法和可玩性

### P1-A1 一次性战术 3 选 1（核心）

- **当前问题**：被克对局 0–21%，第 3 回合未行动就倒下；每回合只有 2 个固定技能，3 回合的最优解几乎固定。
- **建议改动**：
  1. 新增 `tactics.ts` 定义 3 个赛前战术（整场生效、一次性选择）：
     - `desperado`「背水一战」：属性被克时，克制系数由 ×0.80 改为 ×1.10，造成伤害 ×1.20，受到伤害 ×0.85；
     - `steady`「稳扎稳打」：造成伤害 ×1.05，受到伤害 ×0.85；
     - `swift`「快人一步」：每回合先手，造成伤害 ×1.08，受到伤害 ×0.95。
  2. `battle.ts` 的 `BattleSide` 增加 `boons` 字段，`computeDamage` 只做系数乘法与 clamp（仍是纯函数）；`createBattle` 接受 `tacticId`；默认不传 = 无战术，旧测试行为不变。
  3. `CardView` 增加"战术"选择（默认按对手属性给出推荐），出战传给 `BattleView`；战斗页与结算页展示本局战术。
- **用户体验收益**：被克对局从"必败"变成"选对战术有真实胜率"；赛前多一个与选对手联动的决策；同一精灵对不同敌人可以换打法。
- **实现复杂度**：中（引擎 + 类型 + 两个界面 + 平衡模拟）。
- **依赖**：无；与 B1 无冲突（战术改变伤害，AI 改变选招）。
- **验收方式**：
  - 单测：三战术的系数只作用于对应局面；同 seed + 同战术 + 同出招可复现；无战术时与 P0 结果逐字节一致（回归保护）。
  - 平衡模拟：被克组合胜率从 0–21% 提升到 **≥25%**（实际 55%–83%：83% / 55% / 77%），优势组合未被压低（多数 100%），平均回合数仍为 3.0。
  - 不选战术时被克仍为 0% / 2% / 22%，说明战术是有效变量而非白送。
  - E2E：卡面能选战术；战斗页显示战术；结算页显示战术。

### P1-A2 同种子复现本局

- **当前问题**：结算页展示种子，但"再来一局"换新 seed，玩家无法验证/重放刚才那局。
- **建议改动**：结算页增加「复现本局」按钮，用 `battle.seed` + 同一战术重开；"同对手再来一局"保留新 seed。
- **收益/复杂度**：低复杂度，兑现"可复现"的产品承诺，也方便演示与录制。
- **验收**：点「复现本局」后战斗页种子与上一局一致；相同出招序列得到相同结果（由引擎测试保证）。

## P1-D：扩展内容、成长机制和重复游玩价值

### P1-D1 战绩持久化

- **当前问题**：胜负不影响任何持久数据，第二次游玩没有目标。
- **建议改动**：
  1. `Monster` 增加可选 `record`（wins/losses/draws/streak/bestStreak/lastOutcome），`store.ts` 增加 `recordBattle` 并向后兼容旧 localStorage 数据。
  2. 结算页显示本局战绩变化与连胜；图鉴卡格与对比区显示 W-L；卡面页脚可显示战绩。
  3. 连胜进入战斗页角标，给"再打一局"一个理由。
- **收益/复杂度**：低成本，直接把一次性对局变成可积累的进度。
- **验收**：单测 `recordBattle` 幂等/累加/最佳连胜；localStorage 旧数据可读；E2E 胜利后图鉴出现战绩。

### P1-D2 机制型敌人（暂缓）

- 反弹、叠毒会扩大规则面与平衡风险，且不解决"没有战绩/没有 AI 对手"的主要矛盾；留到 P2 再评估。

## P1-C：增强视觉、交互反馈和整体沉浸感

### P1-C1 战斗反馈

- **当前问题**：HP 条瞬变、无回合横幅、KO 与"比血"共用同一块结算条、最新战报不高亮、意图无来源。
- **建议改动**（全部 CSS + 少量 TSX，不改规则）：
  1. HP 条宽度过渡 0.45s；扣血时血条闪红。
  2. 每回合切换显示「第 N 回合」横幅（0.9s 淡出）。
  3. 一方 HP 归零时显示巨型「胜/负/平」印章定格动画，再出现结算条。
  4. 战报最新一行高亮；AI 选中回合的意图条加红点脉冲与 `AI 选招` 徽章。
  5. 意图条补充"这一击会不会把我打倒"的判断（由规则计算，不引入随机）。
- **收益/复杂度**：低成本、高体感收益；不动战斗规则。
- **验收**：E2E 截图肉眼检查；不出现布局溢出（375px）；所有动画可被 `prefers-reduced-motion` 关闭。

### P1-C2 结算页复盘增强

- 显示本局战术、AI 参与次数/模型/耗时、战绩变化、复现入口；关键行动高亮造成最多伤害或最后一击。
- **验收**：E2E 结算页出现对应字段；数据来自真实 `battleState`，不是静态文案。

## P1-E：工程质量、性能与稳定性

### P1-E1 服务端计划接口与限流

- 统一 `callModel` 供 analyze / battle-plan 复用；计划请求 zod schema；响应 zod；超时 12s（计划比出卡短）；分接口限流（analyze 20/min、plan 60/min），避免 P1 每局 3 次调用触发 429 误降级。
- 对畸形 URL 的 decode 失败做兜底；请求体超限统一处理；错误统一 JSON。
- **验收**：真实接口冒烟脚本通过；限流下第 N+1 次返回 429 且界面降级为规则意图而非崩溃；无 Key 时 503，前端直接走规则。

### P1-E2 ErrorBoundary + 懒加载 + 图鉴 Bug

- 新增 `ErrorBoundary`（纸张风格回退页 + 重新加载按钮）。
- `share.ts` 改为动态 `import()`，从首屏 chunk 拆出。
- 修复图鉴对比"克制倍率"行实际显示技能名的 Bug，改为显示真实 `typeMultiplier`。
- **验收**：构建产物体积/分块变化记录；模拟渲染异常不白屏；图鉴行显示 ×1.25/×1.00/×0.80。

### P1-E3 测试补齐

- 新增/扩展：战术系数与可复现、AI 计划 sanitize/apply/降级、`recordBattle`、计划页面 E2E 断言、真实接口冒烟。
- **验收**：`npm test` 全绿且新增用例覆盖上述规则；`npm run shots` 全绿；`node scripts/ai-check.mjs` 真实模型通过。

# 江城万物怪 2.0 · 平衡与验收方案

> 版本：V1.0（2026-11-19）｜依据：`JIANGCHENG_2_GDD.md`、`JIANGCHENG_2_ARCHITECTURE.md`、P1 实测数据
> 原则：**不允许只看单个总胜率就宣称平衡完成**；每个结论都要有可复现的模拟/试玩证据。所有数值为【设计初值】，Batch 1/2 用模拟与试玩调参。

## 1. 平衡框架

### 1.1 设计目标

1. **物品价值 ≠ 战力**：预算恒定（68–75 等效点），差异来自机制职责而非数值。
2. **每场战斗至少两个真正不同的有效选择**（输出/守护/换位/控制/支援/连携）。
3. **被克仍可打**：被克阵容靠构筑/战术仍有 30%+ 胜率（不是必败）。
4. **Boss 有多解**：每个 Boss 至少 2 种构筑可通关，没有单一构筑全 Boss 碾压。
5. **成长是横向的**：等级上限 5，每级 ≤+2 等效点；进化改变职责。
6. **无死锁/无 NaN/无无限回合**：纯函数 + 回合上限 + 模拟检测。

### 1.2 v2 数值初值（Batch 1 可实现，随后调参）

**单位数值（沿用 P1 区间）**

| 属性 | 区间 | 说明 |
|---|---|---|
| HP | 65–100 | 与 P1 一致；主战承受伤害，支援有独立 50 HP |
| ATK | 18–35 | 与 P1 一致 |
| DEF | 5–20 | 与 P1 一致 |
| SPD | 5–20 | 先手/同速种子排序 |
| 数值预算 | `hp/5 + atk + def + spd ∈ 68–75` | P1 五样本实测 69–74，作为硬约束 |
| 等级 | 1–5 | 每级 +2 等效点（二选一） |

**伤害公式（v2）**

```
raw = power + 0.45×ATK − 0.30×DEF
damage = clamp( round(raw × 类型系数 × 状态修正 × 连携修正 × 0.62), 3, 55 )
类型系数：克制 1.25 / 中性 1.0 / 被克 0.80（沿用 P1）
```

**典型值**（用于核对量级）：

| 场景 | 计算 | 结果 |
|---|---|---|
| 普通技能 22 威力，ATK 28，敌 DEF 12 | 22+12.6−3.6=31 ×1.0×0.62 | 19 |
| 克制本系 | 19 ×1.25 | 24 |
| 被克 | 19 ×0.80 | 15 |
| 主战 HP 80 被连续命中 | 80 / 22 | 约 4 次倒下（换位有意义） |
| Boss 单体 24 威力，ATK 30 | 24+13.5−3.6=33.9×0.62 | 21 |
| Boss 关键机制 | 21 ×1.3（过热/暴雨加成） | 27 |

**回合与资源**

| 项 | 值 |
|---|---|
| 普通战回合上限 | 7（Boss 8） |
| 玩家每回合行动 | 1 主战行动 + 1 支援指令 |
| 共鸣初始/上限 | 2 / 6 |
| 共鸣获取 | 克制命中 +1；防御/支援 +1；被机制命中可能 −1 |
| 共鸣消耗 | 换位 1、强主动 1–2、连携 2、部分支援 1 |
| 每场连携 | 1 次 |
| 主战倒下 | 下一位支援 30% HP 入场；三人全倒判负 |

**模块/被动预算**

| 项 | 约束 |
|---|---|
| 已知主动 | 3 个（编译产生） |
| 装备主动 | 2 个 |
| 被动 | 1 个 |
| 装备主动总消耗 | ≤8 |
| 被动消耗 | ≤3 |
| 总消耗 | ≤11（防止“全带最强技能”） |

**状态上限**

| 状态 | 上限 | 持续 |
|---|---|---|
| 湿潮 | 3 层 | 2 回合 |
| 缠绕 | 1 层 | 消耗一次行动 |
| 脆弱 | 1 层 | 2 回合 |
| 护盾 | 按数值（≤30） | 2 回合 |
| 蓄力 | 3 层 | 攻击消耗 |
| 反光 | 1 层 | 1 回合 |
| 过热（Boss） | 5 层 | 阶段清空 |
| 标记 | 1 层 | 2 回合 |

**经济（≤3 资源）**

| 资源 | 来源 | 消耗 | 防刷 |
|---|---|---|---|
| 探索补给 | 进入区域初始 3；休整 +1；事件 +1 | 进入区域 1；复活/重开 1 | 每次进入消耗，不能囤无限 |
| 成长材料 | 节点 1–3；Boss 3–5 | 升级 2；模块变体 3；进化 5 | 重复刷同节点收益 −50%，每日软上限按会话计 |
| 区域信物 | 区域首次通关 1；挑战变体 1 | 进化/回退/挑战 1 | 每区域每档限一次 |

## 2. 模拟方案（1000+ 局）

### 2.1 战场矩阵

- **队伍构筑**：6 种（守护流/爆发流/控制流/支援流/机动流/混合流）× 2 个区域 Boss = 12 组。
- **每个组合** 100 局（固定 seed 集 0..99，便于复现），共 **1200 局**。
- **策略**：4 种 AI 玩家脚本（直伤/轮换/换位/保守），至少覆盖 2 种；报告按策略拆分。
- **对手**：区域普通组合（4 个敌人原型组合）+ Boss。

### 2.2 必须报告的指标

| 指标 | 目标 |
|---|---|
| 胜率（匹配构筑 vs Boss） | 40–70% |
| 胜率（随机/不匹配构筑） | 10–35% |
| 被克阵容胜率 | ≥30%（靠连携/控制/守护） |
| 平均回合数 | 5.5–7.5（Boss），4–6（普通） |
| 超过回合上限 | 0 局 |
| NaN / 负血 / 状态超过上限 | 0 局 |
| 单一构筑对全部 Boss 胜率 >85% | 0（退化组合） |
| 每个 Boss 可通关构筑数 | ≥2 |
| 共鸣空转（有技能但 7 回合无法使用） | <5% 局 |
| 连携使用率 | 匹配构筑 ≥60% 局至少 1 次 |

### 2.3 实现方式

- `src/domain/battle2/__tests__/balance.test.ts`（不参与 CI 断言，打印表格；关键阈值用 `expect` 保护）。
- `scripts/balance-2.mjs` 输出 Markdown 报告（游戏名/构筑/Boss/胜率/回合/击倒/异常）。
- 种子：`sim-${buildId}-${bossId}-${i}`；同 seed 同日重跑结果一致（回归测试）。

## 7. 复玩与留存验收（可证伪）

### 7.1 “第一次好玩”标准

- **90 秒内**：完成“选样本/拍照 → 召唤 → 看到能力来源”；5 人测试 ≥4 人做到。
- **3 分钟内**：进入并完成首场战斗；≥4 人。
- **60 秒内**：能说出“我选的守护分支让伞挡住了雨”；≥4 人。
- **无帮助操作**：不读教程、不看说明，≥3 人独立完成首个节点。

### 7.2 “第二次仍想玩”标准（行为，不是问卷）

- 首次会话结束后 10 分钟内，≥3/5 主动做以下之一：进入第二区域 / 再捕获一件物品 / 打开进化预览并做出选择。
- 首败后，≥3/5 会改变队伍/技能/分支再战，而不是原样重试。
- ≥3/5 能指出自己两只怪的机制差异（不是数值差异）。
- 打开图鉴时，≥3/5 会点开“未发现线索”或尝试补图鉴。
- 若以上任一未达到：优先修核心机制（编译器/战斗决策/演出），不扩美术和任务文本。

### 7.3 试玩协议（5–10 人）

- 招募：未参与开发的学生 5–10 人，尽量覆盖“手游玩家/非玩家”。
- 流程：① 不讲解，观察 10 分钟；② 记录时间、失败点、主动行为；③ 结束后 5 分钟访谈（3 个问题：你最想留着哪只？为什么？下一步想做什么？）。
- 记录表：`docs/JIANGCHENG_2_PLAYTEST_LOG.md`（实施时创建）。
- 禁止：引导性提问、代为操作、用问卷代替观察。

# 江城万物怪 · 观测手册

> 拍下一件寻常物品，它会变成你的专属精灵，然后立刻打一场三回合战斗。
> 这是《珞珈 AI 创意实验场》规格书里 **P0-B → P1** 的可玩原型，不是概念稿。

- 无模型 Key 也能完整游玩：自动进入 **演示模式**，界面明确标注「演示模式」，不伪装成实时生成。
- 有 Key 则走 **实时 AI**：模型负责命名、设定、造型与视觉识别，**并在战斗里担任敌方指挥官——在合法招式内选招**；属性、数值、伤害、胜负结算仍由规则引擎决定。
- 当前接入并实测：**武大 MaaS · `deepseek-v4-flash`**（可读图、可稳定输出 JSON；出卡 1.2–9 秒、带图 4–18 秒；敌方决策 1.8–5 秒，偶发长尾）。
- P1 新增：赛前 3 选 1 战术、战绩/连胜、同种子复现、战斗演出与 AI 决策标注。详见 [`docs/P1-RESULT.md`](docs/P1-RESULT.md)。

## 一条完整的游玩闭环

```
进入首页（0 秒）
  → 点「芝麻旋旋」样本卡（≤3 秒拿到卡）
  → 卡面看到：属性 / 数值 / 两个技能 / 来自照片的可见特征
  → 选择对手（默认已按属性克制排好）+ 选择本局战术（背水一战 / 稳扎稳打 / 快人一步）
  → 三回合战斗：先看敌方 AI 的意图与战况播报，再决定爆发 / 防御 / 回血 / 抢手
  → 结算：胜负、AI 参与回合、战术、战绩变化、伤害依据、可复现种子
  → 复现本局 / 同对手再战 / 保存精灵卡 PNG / 图鉴对比出战
```

首页到第一次有效操作只隔一次点击；实测节奏（本地）从点击样本到进入战斗约 5–8 秒，满足规格书「首场战斗 ≤60 秒」。

## AI 到底做了什么

| 环节 | 谁负责 | 说明 |
|---|---|---|
| 读取图像、降采样、主色统计 | 本地规则 | 浏览器 canvas，64×64 采样，不读 EXIF |
| 物体类别 / 可见特征 | 实时 AI（有图时）或本地色相规则 | 结果带 `confidence` |
| 名称、气质文案、造型配方 | 实时 AI（受白名单约束）或本地命名器 | 禁夸张词、禁现有 IP、名字 ≤8 字 |
| HP / 攻击 / 防御 / 速度 | 规则引擎 | 互补式分配，区间固定，同一输入可复现 |
| 技能槽 | 规则引擎 | 固定 6 技能白名单，至少 1 个能造成伤害 |
| **敌方每回合出招** | **实时 AI（P1）** | 模型只看当前可见状态，在敌方合法招式里选一个，返回理由与战况播报；超时/失败自动回落规则意图并标注 |
| **战况播报** | 实时 AI（P1） | 与选招同一次调用返回 `taunt`，只做氛围，不影响任何数值 |
| 战术系数 / 伤害 / 胜负 / 天气 | 规则引擎 | 纯函数，同种子 + 同战术 + 同出招 = 同结果；AI 不能改数值 |

三种模式在界面上始终可见：

- `实时 AI`（红章）：真实请求了模型，调用记录里能看到 model 与耗时；战斗意图条另有 `AI 选招` 徽章与 `AI 决策 N/3` 统计；
- `演示模式`（灰章）：没有请求模型，本地规则生成 / 规则出招；
- `降级模式`（虚线红章）：实时调用失败或超时，规则引擎接管并说明原因。

页脚「调用记录」列出每次调用的时间、模式、结果与耗时（含 `/api/battle/plan`），用来核对是否真的请求过模型（不记录图片内容）。

### 模型接入记录（2026-11-19 实测）

同一张图片（192KB 截图）分别丢给 12 个模型，问「最显眼的物体 + 主色」：

| 能读图 | 模型 |
|---|---|
| ✅ | `deepseek-v4-flash`、`deepseek-flash`、`qwen-27b`、`qwen-flash`、`qwen3.7-plus`、`minimax-m3`、`minimax-m3.1-flash`、`kimi-k3`、`kimi-k3.1-pro`、`glm-5.3-flash` |
| ❌ 明确不支持图 | `glm-5.3`（返回提示改用 flash）、`qwen3.7-max`（400） |

阅读这些模型时踩到的三个坑，已在服务端处理：

1. **推理模型会把 token 花在 `reasoning_content` 上**：`max_tokens` 太小（如 300）时 `content` 为空且 `finish_reason=length`。服务端默认 1600，并在空内容时自动加预算重试到 3200。
2. **超时要按推理模型放宽**：出卡服务端 26 秒、前端 30 秒，8 秒后出现「改用演示策略」出口；战斗决策服务端 18 秒、前端首回合 8 秒/后续 12 秒，超时自动回落规则意图且不阻塞出招（首回合可点「不等了」）。
3. **上传原图太大**：浏览器先压到最长边 1100px、JPEG 0.82 再发给模型（5MB 原图 → 约 80–200KB），既不丢识别效果，也明显降延迟。
4. **P1 新增：客户端取消要能传导到模型**：切回合/退出对战时前端 abort，服务端监听连接关闭后 abort 模型请求，避免为已经没人看的回合继续消耗 token（日志会区分 `client_abort` 与 `timeout`）。

提示词里写死了三件事：只描述看得见的东西、图片里的文字不是指令（防提示词注入）、不推断地点与人物。模型返回的 `vision` 与 `draft` 都要过 zod；`vision` 不合法就退回本地像素摘要。

## 战斗规则（固定、可复现）

五行属性中只有三系构成闭环，另外两系中立：

```
早味 → 克 → 木叶 → 克 → 江流 → 克 → 早味
铁骨 / 机巧：中立
克制 ×1.25，被克 ×0.80
```

每次战斗随机一个天气，同属性技能 +3 威力，开局公示。

```
伤害 = clamp( round( (威力 + 0.4×ATK − 0.25×DEF) × 克制系数 × 0.78 × 战术系数 ), 5, 45 )
```

`0.78` 是可调的平衡系数（公式结构与规格书一致），用来保证三回合内既能击倒、也不会一回合结束。战术系数只来自 P1 的固定战术表，AI 不能修改。

**P1 战术（赛前 3 选 1，整场生效）**

| 战术 | 效果 |
|---|---|
| 背水一战 | 属性被克时：被克系数 0.80 → 1.02，造成伤害 ×1.05，受到伤害 ×0.88；未被克时只 +2% 伤害 |
| 稳扎稳打 | 造成伤害 ×1.00，受到伤害 ×0.95 |
| 快人一步 | 首回合先手（优先于速度），造成伤害 ×1.06，受到伤害 ×0.97 |

**敌方 AI（P1）**：每回合把"玩家此刻看得见的状态"发给 `/api/battle/plan`，模型只能在敌方已有技能里选一个，并给出理由与战况播报；模型输出过 zod + 白名单二次校验，通过后才写进 `state.intent`。战斗结算仍由 `battle.ts` 纯函数完成，所以同 seed + 同计划序列 + 同出招 = 同结果。无 Key / 超时 / schema 不过时自动回落规则意图，意图条与结算页会如实标注。

技能池（固定 6 个，每只精灵带 2 个；第一槽固定为本系「元素爆发」保证强度下限，第二槽采纳模型偏好）：基础冲击 18 / 元素爆发 24 / 抢先一步 15（优先行动）/ 佯攻 12（下次攻击 +8）/ 稳固防御（本回合减半）/ 小憩回血（+16，单局限一次）。

回合结算：按优先级 → 速度 → 种子决定先后；任一方倒下立即结束；三回合未分胜负比剩余 HP 百分比，差 1 个百分点内为平局。

### 平衡现状

`npm test` 会打印两组表：5 只样本 × 4 个对手的「无战术 / 推荐战术」胜率对比（每格 60 局，一步前瞻策略）与三战术横评：

- 属性被克：无战术 0% / 2% / 22%，选「背水一战」后 **83% / 55% / 77%**（这是 P1 的核心修复：被克局不再必败）
- 属性中性：53%–100%（推荐「稳扎稳打」）
- 属性占优：多数 100%（推荐「快人一步」）
- 平均 3.0 回合结束，三回合封顶不变

样本数值与胜率表都在测试输出里，调参即改 `enemies.ts` / `build.ts` / `tactics.ts` 后重跑。

## 隐私与合规

- 默认不上传照片：降采样与主色统计都在浏览器完成；开启实时 AI 时界面会提示「这张图会发送给模型服务用于识别」。
- 不读 EXIF，不做人脸识别、地点判断或打卡验证；照片不落盘、不进 localStorage、不写服务端日志。
- 图鉴只存精灵卡数据（名称、属性、数值、造型配方、本机战绩），可单条删除。
- 战斗 AI 只发送局面数值与技能名，不发送照片；提示词明确"只选合法招式"。
- 所有精灵、NPC、场景均为原创虚构，不使用学校官方标识，不冒充校方服务。

## 已知问题

- 被克局仍很依赖「背水一战」：选对战术胜率 55%–83%，选错或不选仍 0%–22%。后续可加战术代价/相性让选择更有取舍（P2）。
- 敌方 AI 决策延迟真实波动（1.8–11.6 秒）：回合 2/3 不阻塞输入，玩家手快时会看到规则意图先出招；首回合最多等 8 秒，可点「不等了」。
- 敌方只有 2 个技能、4 个固定敌人，AI 的选择空间有限；加机制型敌人后 AI 决策观感会更好（P2）。
- 把游戏截图当照片上传时，模型会把「卡片底、竖向构图」也当成画面特征写进证据标签（它没说错，只是这类输入本身是元图像）。真实拍摄的物体没有这个问题。
- 推理模型带图约 4–18 秒，比样本路径慢；演示时建议先用样本。
- 图鉴上限 24 只，超出后最早一只被移除（未做「锁定收藏」）。
- 移动端首页的示例大卡较高，需要滑动才能看到五个样本条。
- `game.css` 末尾新增了「P1 增补」样式块，后续可合并去重。
